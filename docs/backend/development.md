# Backend development

The backend owns fleet/user records, telemetry persistence, mower provisioning,
Zenoh ACL reconciliation, signed cutout URLs, and LiveKit credentials. Native
Zenoh routes are the operational interface; FastAPI supplies process lifecycle
and the health endpoint.

## Setup

Install Python 3.12 and [uv](https://docs.astral.sh/uv/), then from `backend/`:

```sh
uv sync
cp .env.example .env
```

Fill the ignored `.env` with database settings, `JWT_SECRET`, service URLs, and
any required Firebase, GCS, or LiveKit configuration. Never commit an `.env`,
Google service credential, Zenoh password, mower private key, or CA private key.

PostgreSQL, Valkey, and Zenoh are normally provided through Docker Compose; no
host installation is needed for the Compose workflow.

## Local stack

Start the local development stack:

```sh
docker compose -f local-docker-compose.yml up -d
docker compose -f local-docker-compose.yml ps
docker compose -f local-docker-compose.yml logs -f backend
```

The stack includes PostgreSQL, Valkey, app/mTLS/bootstrap Zenoh routers,
FastAPI, telemetry and credential-expiry workers, and a one-shot ACL
reconciler. On Linux it uses host networking. PostgreSQL and Valkey volumes
survive normal `down`; `down -v` deletes local persistent data.

For a smaller local stack, start PostgreSQL, Valkey, the app and mTLS routers,
and FastAPI, then run:

```sh
docker compose -f local-docker-compose.yml run --rm add-all-acls
```

Start `upload-telemetry` and `remove-usrpwds` when exercising their respective
background lifecycles. See [Docker](docker.md) and
[Zenoh routers](zenoh-routers.md) for service details.

## Migrations and local data

```sh
uv run alembic revision --autogenerate -m "describe change"
uv run alembic upgrade head
uv run python -m src.scripts.seed_fake_mowers
```

Inspect autogenerated migrations before applying them. The seed script requires
its development user to have signed in once. `src.scripts.clear_all_data` is a
destructive local reset; use it only when deleting every application table and
the configured Valkey logical database is intended.

## Contract generation

`zenoh_asyncapi.yaml` is the native Zenoh contract source of truth. After a
contract change, install the AsyncAPI CLI and regenerate from `backend/`:

```sh
npm install --global @asyncapi/cli
sh tools/generate_types.sh
```

The command affects backend, app, and Jetson generated bindings. See
[AsyncAPI generation](asyncapi-generation.md) before modifying it.

## Quality checks

```sh
uv run ruff check .
uv run ruff format --check .
uv run pytest -m 'not repository and not api and not zenoh_integration'
uv run pytest --run-integration
```

The integration invocation requires Docker. See [testing and quality](testing.md)
for coverage, test layers, and formatting/fix commands.

## Certificate and mower operations

Certificate issuance, router ACL changes, mower initialization, and TPM renewal
cross trust boundaries. Do not run those as ordinary local setup. Refer to
[certificates](certificates.md), [mower initialization](mower-initialization.md),
and the operational provisioning procedure before acting on a real mower.
