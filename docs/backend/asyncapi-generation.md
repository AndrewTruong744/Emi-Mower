# AsyncAPI-based Zenoh generation

**Source of truth:** [`backend/zenoh_asyncapi.yaml`](../../backend/zenoh_asyncapi.yaml).
It defines native Zenoh channel addresses, operations, messages, and schemas
shared by the backend, mobile app, and Jetson gateway. It is not a REST/OpenAPI
document and does not define ROS IDL.

## Regeneration workflow

From `backend/`, install the generator's locked dependencies, then run:

```sh
npm ci --prefix tools
npm --prefix tools run generate
```

The npm command uses the locally installed AsyncAPI CLI to validate the
document, then runs `tools/generate_zenoh_bindings.mjs`. The language renderers
read AsyncAPI schemas directly and generate Python, TypeScript, and Rust types.
The generated files contain wire types only. They represent field types,
required fields, nullable values, arrays, unions, protocol choices, and
defaults for omitted telemetry fields. Nullable fields use JSON Schema null
unions; a required nullable field remains required. The schema leaves value
rules such as ranges and date or URI parsing to the receiving functions.
Unknown fields are allowed by the contract. Channel addresses generate all
three languages' path helpers.

The entry point loads the contract and writes or checks outputs. Its
`tools/zenoh_bindings/` modules hold shared schema handling, one type renderer
per language, and the path renderers. Modelina is not called by this generator.

Review every generated diff and commit compatible updates across all affected
consumers. To verify that committed outputs are current without writing them,
run `npm --prefix tools run check` from `backend/`.

## Generated outputs

| Generator                           | Outputs                                                                                       |
| ----------------------------------- | --------------------------------------------------------------------------------------------- |
| `tools/generate_zenoh_bindings.mjs` | Backend Pydantic models and paths; app TypeScript models and paths; gateway Rust types and paths. |
| AsyncAPI CLI                        | Validates the contract before generation.                                                    |

Committed generated locations include `backend/src/zenoh/generated/`,
`app/src/generated/`, and the Jetson gateway generated directory.
Do not hand-edit generated path or type outputs. If a schema needs an output
that the current generator does not cover, change the generator and add a
contract test rather than patching one consumer's generated file. ROS `.msg`
types remain generated by ROSIDL from ROS message definitions, outside this
AsyncAPI workflow.

## Safe contract changes

1. Edit `zenoh_asyncapi.yaml` first and consider compatibility for every
   producer and consumer.
2. Regenerate all bindings from `backend/`.
3. Update handlers, services, ACL assumptions, app code, and gateway code as
   needed.
4. Run backend contract tests and affected app/gateway tests. A command,
   telemetry, identity, or deployment change requires cross-layer verification.

The backend telemetry contract tests detect drift between the AsyncAPI schema
and generated payload shapes. The AsyncAPI CLI checks that the document is
valid; focused app, backend, and gateway tests cover value rules at the
functions that consume those messages.
